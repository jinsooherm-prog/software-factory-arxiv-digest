Coding agents are outgrowing the text editor, and nobody has fully checked their work yet

A theme running through today's crop of papers is that "coding agent" has quietly become a general-purpose production method, not just a tool for fixing GitHub issues, while the basic question of whether their output is actually correct or necessary keeps getting harder to answer. The most direct look at that question comes from How Much Do Coding Agents Over-Edit, and Why?, which replays over 7,600 resolved Copilot CLI trajectories across 18 frontier models and traces every line of a patch back to the step that wrote it. The headline finding cuts against the usual assumption that bigger patches mean sloppier agents: most of the "extra" edits are tests and documentation rather than wasted code, and agent-written code is, on average, at least as necessary as a human developer's — though roughly 11% of it is still dead weight, and necessity varies wildly by model with no clean link to benchmark resolve rate. SmartLens tackles the adjacent problem of living with that output day to day: an IntelliJ plugin that attributes pending changes to human or agent, flags which APIs and language features an agent used that the developer has never touched, and ranks files as review-risk hotspots — a reminder that once agents are prolific contributors, the real bottleneck shifts from writing code to knowing what to trust and learn from.

The other half of today's batch shows coding agents being pointed at domains well outside conventional software engineering, treating "write and run a program" as a general substrate for building things that used to require bespoke generation pipelines. WebVibe trains a compact model to generate fully interactive, multi-page websites from design specs by reversing the usual synthesis order — deriving the spec from verified browser replay instead of the other way around — and gets a 9B model to match a trillion-parameter coding agent on functional website scores. Solve Vision with Code goes further, pitting coding agents directly against video-generation models on visual reasoning tasks and finding that agents which write a rendering program to produce the answer beat native pixel-generation models by a wide margin, suggesting symbolic program synthesis is currently the more reliable route to visual reasoning. In a similar vein, SemProxy has coding agents turn simple labeled 3D bounding boxes into full 3D models, letting users specify spatial intent while leaving geometry to the agent, and VibeVideoAgent gives code-driven video-generation agents a way to actually watch their own draft renders — catching overlapping subtitles or out-of-sync narration that a clean program exit would otherwise hide — and shows measurable quality gains across Claude and GPT-6 Astra. Taken together, the day's work argues that coding agents are becoming the default way to produce almost any structured artifact, which only raises the stakes on the auditing and attribution problems the first two papers are trying to solve.
