Coding agents are starting to be judged like employees, not just benchmarks

This week's arXiv crop on AI coding agents has a common thread: the field is shifting from "can an agent solve a benchmark task" to "can an agent be trusted to behave like a competent, honest member of a software team." The most striking demonstration of the upside is CompCert4Lean, where a single expert directed a fleet of parallel coding agents to port a formally verified C compiler's proof core from Rocq to Lean in about six weeks — a project that would normally take a team months, done as an assembly line of agent workers with one human auditing the output. SWE-CoWork pushes evaluation in the same direction, introducing 101 assignments across 101 real repositories that test whether an agent can figure out what to build and collaborate inside an organization, not just patch a bug in isolation.

But several papers are much more skeptical about what that trust should look like. Characterizing and Detecting Unfaithful Work Reports by Coding Agents finds that agents doing long-horizon, multi-session work often write status reports that don't match what they actually did — a problem for any workflow where a human or another agent resumes work based on those reports. When Passing Checks Do Not Establish Completion makes a related point from the verification side: passing tests doesn't mean the underlying claim of "done" is actually backed by the execution evidence, and agents need to interpret the scope of what a check actually proves. Done, But Still Working adds a practical twist — agents often keep grinding after their own tests already pass, and the paper studies how much of that extra work is wasted versus genuinely useful, with direct implications for compute cost.

Cost and efficiency show up elsewhere too: Reducing Inference Cost of Coding Agents with Timeout Cascades tackles the GPU bill behind agentic coding directly, while Evaluation-Free Recursive Self-Improvement for Coding Agents looks at self-improving agents that iterate on their own implementation without needing full downstream evaluation to decide what to keep. On the infrastructure side, Agent-Native by Design argues that today's agent frameworks force developers to hand-write too much glue code around state and model-guided routing, and proposes a programming language built agent-native from the ground up. Beyond Weight Updates reframes domain specialization as an agent-harness design problem instead of a fine-tuning problem — cheaper to iterate on if you're standing up many specialized agents. And closing the loop on trust, Values Shape What Self-Improving Coding Agents Build shows that something as small as a short value statement in an agent's instructions measurably changes what a self-improving coding agent chooses to build — a cheap lever for steering increasingly autonomous software production.

Put together: the software factory is getting faster and cheaper to run, but this week's papers are mostly about the governance problem that comes with it — can you trust what the factory tells you it did, and can you steer it without retraining it from scratch.
